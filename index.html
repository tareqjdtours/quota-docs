    Quota Dashboard Runbook

    How to deploy, look after and fix the Quota Dashboard (the quoting tool for Jordan Select Tours and Jordan Direct Tours). Written for whoever is on duty, including when the usual person is away. Every page is a short list of steps.

    Something is broken right now?

    Go straight to The site is down: first five minutes.

    What it is made of

    Box What it does
    frontend The website staff open (nginx). It also passes requests to the backend.
    backend The brain: prices quotes, builds offers and PDFs, sends email, hands booked quotes to the CRM.
    db The database (PostgreSQL). All quotes and the catalogue live here.
    backup A helper that saves a copy of the database every night.

    All run together with Docker Compose. A volume is the folder Docker keeps data in, so data survives restarts. The ones that matter: pgdata (the database) and backups (the nightly copies). The pictures offers show are in a separate folder on the server (MEDIA_ROOT), not in the database.

    Unlike the CRM, nothing deploys by itself

    When code is pushed to GitHub, robots only test it. They do not update the server. Someone must log in and run the update steps. That also means the database update is a separate step you must run yourself.

    The golden rules

    1. Back up before any update. See Backups.
    2. Never delete a Docker volume. Never run docker compose down -v or docker volume prune.
    3. After every update, run the database update step, or pages will error.
    4. Read the error before you act. Start at the site-down page.
    5. Write down what you did, with times.
